# Как это всё работает

## Проблема

Блокировки VPN бывают разные. Самый примитивный способ — заблокировать IP. Но умные системы вроде ТСПУ (Россия) или GFW (Китай) анализируют сам трафик. Они видят что на 443 порту висит не веб-сервер, а что-то непонятное — и блокируют.

Ещё есть **активное зондирование**. Система блокировки сама подключается к твоему серверу и проверяет что он отдаёт. Отправляет TLS ClientHello, смотрит на сертификат, делает HTTP-запрос. Если получает что-то подозрительное — сервер в бан.

VLESS+REALITY с nginx fallback решает обе проблемы.

---

## Идея REALITY

Обычный VPN-сервер имеет свой сертификат. Его можно проверить — домен подозрительный, владелец неизвестный, сертификат только что выпущен. Всё это признаки VPN.

REALITY делает иначе. Вместо своего сертификата — он **"одалживает" сертификат у крупного сайта**. В нашем случае у Microsoft.

Когда зондировщик подключается к серверу на 443 — он видит **настоящий сертификат Microsoft**. Не поддельный, не самоподписанный — реальный, выданный DigiCert, проверяемый через Certificate Transparency. Потому что Xray в реальном времени проксирует TLS-рукопожатие с серверами Microsoft и отдаёт зонду именно их ответ.

## Схема нашей установки

```
                        ┌─────────────────────────────────────┐
                        │           Сервер ноды               │
                        │                                      │
  VPN клиент ──────────►│  :443 Xray (VLESS+REALITY)          │
  (знает ключ)          │     │                                │
                        │     ├── клиент опознан ──────────────┼──► интернет
                        │     │                                │
  Зондировщик ─────────►│     └── не клиент → fallback         │
  (не знает ключ)       │              │                       │
                        │              ▼                       │
                        │  :8080 nginx (127.0.0.1 only)        │
                        │              │                       │
                        │              ▼                       │
                        │      www.microsoft.com               │
                        │                                      │
                        │  :2222 Remnawave Node API            │
                        └─────────────────────────────────────┘
```

---

## Что видит зондировщик

1. Подключается на 443
2. Получает **настоящий сертификат Microsoft** (DigiCert, валидный, проверяемый)
3. TLS fingerprint — **firefox** (Xray имитирует браузер)
4. Делает HTTP-запрос — получает **реальную страницу Microsoft**

Для системы блокировки это выглядит как обычный веб-сервер Microsoft. Блокировать такой сервер — значит блокировать Microsoft целиком.

---

## Как Xray различает своих и чужих

Секрет в криптографии. У каждого VPN-клиента есть:

- **publicKey** — производная от приватного ключа сервера (x25519)
- **shortId** — короткий идентификатор

В процессе TLS-рукопожатия клиент математически доказывает что знает ключ — без каких-либо явных маркеров в трафике. Сниффер смотрящий на трафик снаружи не видит ничего подозрительного.

Если Xray не распознаёт клиента — соединение молча уходит на fallback. Никаких ошибок, никаких подсказок что здесь VPN.

---

## Роль nginx

nginx на `127.0.0.1:8080` — обратный прокси на `www.microsoft.com`. Если зондировщик прошёл через fallback и сделал HTTP-запрос — получает настоящий HTML Microsoft.

Важно: nginx слушает **только на 127.0.0.1**. Снаружи порт 8080 недоступен, к нему можно попасть только через Xray.

## Слои защиты

| Что проверяет цензор | Что видит |
|---------------------|-----------|
| IP-адрес | Обычный сервер, не в списке блокировок |
| TLS-сертификат | Microsoft (DigiCert, валидный) |
| TLS fingerprint | Firefox браузер |
| Активный зонд (HTTP) | Реальная страница Microsoft |
| Паттерн трафика | Не отличим от HTTPS |

## Единственная слабость

Поведенческий анализ. Реальный браузер не держит соединение с Microsoft 30 минут — VPN-клиент держит. Теоретически это можно поймать. На практике такой уровень анализа дорог и применяется редко. Протоколы вроде XTCP и мультиплексирование частично решают и эту проблему.

## Проверка что всё работает

```bash
# С сервера — что отдаёт fallback
curl -s http://127.0.0.1:8080/ | head -20

# Со своего компьютера — имитируем зондировщика
curl -sk --resolve www.microsoft.com:443:89.125.33.47 https://www.microsoft.com/ | head -20

# Проверяем сертификат
echo | openssl s_client -connect 89.125.33.47:443 -servername www.microsoft.com 2>/dev/null | openssl x509 -noout -subject -issuer
```
